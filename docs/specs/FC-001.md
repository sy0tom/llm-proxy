# FC-001: モデルルーティング

## 目的

リクエストのモデルIDから、接続先のProviderと実モデルを解決する規則を定める。

## 対応する要求

| 要求No. | 要求                                                             |
| ------- | ---------------------------------------------------------------- |
| FR-01   | リクエストのモデルIDに応じて接続先のLLM Providerを切り替えられる |
| FR-05   | モデルIDのワイルドカード指定に対応する                           |
| NFR-15  | 未定義のモデルへのリクエストは拒否する                           |
| NFR-16  | 意図しないクラウドLLMへのフォールバックを行わない                |

## 仕様

モデルIDの解決は以下の優先順位で行う。

1. 完全一致
2. ワイルドカード一致
   - 複数の設定に一致する場合は最も長いプレフィックスを優先する。
3. 一致する設定が存在しない場合はエラーを返却する。

一致しない場合に、別のモデルやクラウドLLMへフォールバックしない。

ルーティングの対象は[設定ファイル](../designs/data/app-config.md)の`models`に定義する。
`claude-*`のようにワイルドカードを指定した設定では、実モデルを変更せず、
リクエストで指定されたモデルIDをそのまま上流へ渡す。

## 受け入れ条件

| ID    | 前提                                                  | 操作                                | 期待する結果                                                          | 確認方法   |
| ----- | ----------------------------------------------------- | ----------------------------------- | --------------------------------------------------------------------- | ---------- |
| AC-01 | `models`に`local-lite`が定義されている                | モデルID`local-lite`を解決する      | `local-lite`に設定したProviderと実モデルが返る                        | 単体テスト |
| AC-02 | `models`に`claude-*`だけが定義されている              | モデルID`claude-sonnet-5`を解決する | `claude-*`に設定したProviderが返り、実モデルは`claude-sonnet-5`のまま | 単体テスト |
| AC-03 | `models`に`claude-*`と`claude-haiku`が定義されている  | モデルID`claude-haiku`を解決する    | 完全一致した`claude-haiku`の設定が返る                                | 単体テスト |
| AC-04 | `models`に`claude-*`と`claude-opus-*`が定義されている | モデルID`claude-opus-5`を解決する   | プレフィックスが長い`claude-opus-*`の設定が返る                       | 単体テスト |
| AC-05 | `models`に一致する設定がない                          | 定義されていないモデルIDを解決する  | エラーになり、別のモデルやProviderに解決されない                      | 単体テスト |

## 対象外

- モデルエイリアスごとの推論パラメータの反映は扱わない。[機能一覧](./README.md)のFC-003で扱う。
- エラーをクライアントへ返す形式は扱わない。各APIの機能(FC-006、FC-007)で扱う。
