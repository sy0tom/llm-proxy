# 仕様との整合のレビュー

機能仕様を正として、実装の差分を読み取り専用でレビューする。ファイルを変更しない。

## 入力

- タスクのIssueの番号、または対象の機能No.
- 機能仕様のパス(例: `docs/specs/FC-001.md`)
- base(省略したら`origin/main`)

## 手順

1. 機能仕様の「受け入れ条件」と「対象外」を読む。タスクのIssueがあれば、本文の「満たす受け入れ条件と完了条件」も読む。
2. 差分を読む。

   ```bash
   git diff --stat <base>...HEAD
   git diff <base>...HEAD
   ```

3. 受け入れ条件ごとに、対応するテストを探す。

   ```bash
   rg -n "FC-xxx" tests/
   ```

4. 受け入れ条件ごとに、次を判定する。
   - テストがあり、`test`の名前にIDがある。
   - テストが、受け入れ条件の前提、操作、期待する結果を確かめている。名前だけで中身が違うものは「不足」にする。
   - 実装が、受け入れ条件を満たしている。
5. 差分にある振る舞いのうち、機能仕様にないものを挙げる。
6. 差分がAPI、設定ファイル、構成を変えているのに、`docs/`が更新されていなければ挙げる。

## 出力

次の形式で返す。推測は推測と書く。

```markdown
| 受け入れ条件 | テスト               | 判定                     | 根拠   |
| ------------ | -------------------- | ------------------------ | ------ |
| FC-xxx AC-01 | <ファイル:行 / なし> | <満たす / 不足 / 未実装> | <理由> |

- 機能仕様にない振る舞い: <ファイル:行と内容 / なし>
- 更新されていない`docs/`: <資料と理由 / なし>
- 結論: <指摘なし / 指摘あり(N件)>
```
